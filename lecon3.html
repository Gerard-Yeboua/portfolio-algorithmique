2️⃣ Synthèse personnelle

Une structure de données définit comment les informations sont représentées en mémoire et manipulées (ajout, suppression, parcours, tri, etc.). La leçon se concentre sur trois structures séquentielles :

  • Limites des tableaux : taille figée, besoin de mémoire contiguë, insertions/suppressions coûteuses (décalages), fusion/scission difficiles. → Motivation pour des structures dynamiques.
  • Listes chaînées : chaque nœud contient une info et un pointeur suivant; accès séquentiel via un pointeur tête. Opérations typiques : test de liste vide, ajout (souvent en tête), parcours, extraction/suppression, insertion au milieu, destruction, copie, sauvegarde. Comparatif (ordre de grandeur) : accès aléatoire O(n) mais insertion/suppression en tête en O(1). Variantes : simple, doublement chaînée, circulaire, doublement circulaire.
  • Piles (LIFO) : opérations empiler (push), dépiler (pop), sommet, est_vide — toutes en O(1). Usages : historique navigateur, undo/redo, récursivité, pile d’appels.
  • Files (FIFO) : opérations enfiler (enqueue), défiler (dequeue), tête, est_vide — en O(1) avec pointeurs tête/queue. Usages : ordonnancement CPU/disque, files réseau, synchronisation.

3️⃣ Application pratique

Dans mon rôle de Stagiaire – Agent Test chez MTN CI, je peux appliquer ces concepts ainsi :

  • File (FIFO) pour exécuter des scénarios de test dans l’ordre d’arrivée (gestion de lots, ordonnanceur simple) et pour modéliser des files d’événements de logs.
  • Pile (LIFO) pour gérer l’historique d’étapes d’un test automatisé (annuler/rétablir) ou naviguer dans les états d’un workflow.
  • Liste chaînée pour des séquences dynamiques (résultats intermittents, flux non bornés) où l’on insère/supprime fréquemment au début/milieu sans payer des décalages coûteux.

Ces choix améliorent la performance, la clarté et la maintenabilité des scripts et outils internes.
