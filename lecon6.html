Leçon 6 : Graphes

1️⃣ Journal d’apprentissage réflexif

Cette semaine, j’ai découvert les graphes, une structure de données non linéaire permettant de représenter des systèmes complexes (réseaux, connexions, dépendances). J’ai compris les notions fondamentales : sommets, arcs, arêtes, chemins, circuits, cycles et connexité. Les différences entre graphes orientés et non orientés, ainsi que les graphes pondérés, m’ont permis de mieux visualiser les usages concrets. Le plus difficile a été la logique des parcours BFS et DFS et leurs implications, en particulier le coloriage (blanc, gris, noir). J’ai également appris comment les algorithmes de Dijkstra et de Prim s’appuient sur ces concepts pour résoudre des problèmes de plus courts chemins et d’arbres couvrants.

2️⃣ Synthèse personnelle

Un graphe est un couple (N, L) composé :

  • N : un ensemble de nœuds (ou sommets)
  • L : un ensemble d’arcs (orientés) ou d’arêtes (non orientées)

  • Types de graphes :
    • Orienté : relation dans un seul sens
    • Non orienté : relation bidirectionnelle
    • Pondéré/étiqueté : chaque arc possède un poids
  • Notions importantes :
    • Chemin : suite d’arcs où chaque extrémité succède à l’origine précédente
    • Circuit : chemin fermé dans un graphe orienté
    • Chaîne : équivalent du chemin mais non orienté
    • Cycle : chaîne fermée
    • Graphe connexe : tout sommet est accessible depuis tout autre
    • Graphe fortement connexe : accessibilité dans les deux sens (orienté)
  • Représentations d’un graphe :
    • Liste d’adjacence : efficace pour graphes peu denses
    • Matrice d’adjacence : efficace pour graphes très denses, mais coûte en mémoire
  • Parcours de graphes :
    • BFS (parcours en largeur) : utilise une file (FIFO)
    • DFS (parcours en profondeur) : utilise une pile (LIFO)
  • Algorithmes classiques :
    • Dijkstra : plus courts chemins (poids positifs)
    • Prim : arbre couvrant minimal

3️⃣ Application pratique

Dans mon rôle de Stagiaire – Agent Test chez MTN CI, les graphes peuvent être utilisés pour :

  • Modéliser les dépendances entre services lors des tests (API → microservices → bases de données).
  • Optimiser les parcours des scénarios de test en analysant les transitions possibles entre états (graphes orientés).
  • Analyser des chemins dans des flux réseaux ou des logs (ex : Dijkstra pour trouver le point d’impact le plus rapide).
  • Créer des dashboards de connectivité montrant comment les différents composants MTN interagissent (graphes non orientés).

Les graphes permettent donc de mieux comprendre les interconnexions techniques, identifier les zones critiques et optimiser certains processus de tests.
